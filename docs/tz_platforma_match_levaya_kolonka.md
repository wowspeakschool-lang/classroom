# «Соедини пары» — перемешивать и левую колонку

Нашла Анна 04.11.2026 на SM1 Unit 7 Test, блок 6: «Слева картинки расположены
в правильном варианте, как идёт по записи. По очереди».

## Что не так

В `MatchBlock` (`src/public/homework/blocks.tsx`) правая колонка перемешивается:

```ts
const rights = matchRights(b)   // model.ts: shuffle(pairs.map(...), b.id)
```

а левая рисуется прямо в порядке `payload.pairs`:

```ts
{pairs.map((pr, k) => ( … <Tile text={pr.left} image={pr.left_image} … /> … ))}
```

Поэтому порядок, в котором пары лежат в payload, виден ученику как есть. Если
задание опирается на запись или на текст, где предметы идут по очереди, левая
колонка повторяет эту очередь, и ответ читается без прослушивания: верхней
картинке — Number 1, следующей — Number 2 и так далее.

В базе 568 блоков `match`, из них 120 с «послушай» в заголовке и 12 с записью
на уровне блока. Мы можем перемешать пары в самих уроках, но правка живёт
ровно до следующего редактирования блока, а новые задания снова лягут по
порядку. Поэтому просим перемешивать в платформе.

## Что просим сделать

Перемешивать **и левую колонку** — своим зерном, чтобы она не совпадала
с правой:

```ts
const lefts = shuffle(pairs.map((pr, k) => ({ pr, k })), b.id + 'L')
```

и дальше рисовать `lefts`, **сохраняя исходный индекс `k`** у каждой пары:
ответ ученика лежит в `ans[k]`, проверка сравнивает его с `pairs[k].right`,
цвет пары берётся по `k`. Если `k` поедет, сломается и проверка, и цвета.

Правая колонка остаётся как сейчас (`matchRights`, зерно `b.id`).

Порядок пар в payload после этого ни на что не влияет — ни у ученика,
ни у учителя.
