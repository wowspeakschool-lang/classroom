## 4. Формат промптов — соблюдать дословно

Анна прогоняет в ChatGPT. Формат выработан опытом:

1. **Вся партия одним блоком кода** — копируется одним движением
2. Сверху строка про количество изображений и требование не останавливаться
3. Блок общих правил (стиль + геометрия листа) — **один раз на всю партию**
4. Дальше листы подряд: номер, тема, размер сетки, «ровно N картинок», нумерованный список, строка `--ar 3:2`

Ограничения:
- **3–4 листа на партию.** С пятого качество падает
- 8–13 картинок на лист. Не 4–6
- Количество указывать дважды: как сетку И как «ровно N картинок»
- Слова `flat design`, `simple shapes`, `minimal detail` дают плоские иконки — **не использовать**
- Листы нумеровать с 1 в каждой новой партии, без пропусков

## 5. Нарезка листов

Скрипты рядом с этим файлом: `lib.py` (библиотека), `recut.py` (пример вызова на заходе 1), `mk.py` (генерация SQL).

Алгоритм:
1. **Профиль по строкам** — считаем в каждой строке пиксели с `min(R,G,B) < 200`, находим пустые полосы, получаем полосы с картинками и полосы с подписями
2. Если полоса картинок слиплась с подписью — ищем внутренний разрыв с порогом `count < 30`, берём то, что выше
3. Внутри полосы — `scipy.ndimage.label` по маске `min_rgb < 235`, компоненты сортируем по X, склеиваем в кластеры с зазором `gap`
4. Проверяем: число кластеров == числу слов. **Не сходится — не подгонять padding, а смотреть колоночный профиль и менять `gap`**
5. Альфа: `make_soft_transparent` заливает только фон, связанный с краем кропа (заливка от границы), плюс мягкая кромка
6. Кладём в канвас 300×300 с отступом 6px

Подобранные значения (заход 1):
- `gap=18` — сетки 4×3
- `gap=12` — плотные сетки 5×2 и 5+4+4
- `min_area=600` по умолчанию; **`min_area=120..150`, если у картинки есть мелкие отдельные детали** (волны тепла у `heating`, линии звонка у `ring (phone)`) — иначе они отваливаются

Известные ограничения:
- У сцен с цветным фоном (комната, скала, снег) фон прямоугольный и прозрачным не станет. Это нормально, выглядит как фото в рамке. Анна в курсе
- Если фон сцены не касается края кропа — он тоже останется. Тот же случай

## 6. Генерация SQL

- Картинки **только base64 WebP data URI**, не bucket (SQL Editor не пишет в object storage)
- WebP 300×300 RGBA, `quality=80, method=6`
- `UPDATE words SET image_url = '...' WHERE deck_id = N AND term = '...'`, обёрнутый в `BEGIN; ... COMMIT;`
- **Идентификация строго по паре `(deck_id, term)`.** Никаких подзапросов по названию папки — в БД есть дубли папок, подзапрос вернёт две строки и упадёт с `21000`
- Апострофы в `term` экранировать удвоением
- **Файл не больше ~500 KB.** Предел SQL Editor где-то между 500 и 850 KB, не рисковать. Резать по колодам
- Отдельный файл на колоду, отдавать через `present_files`
- Сверять набор пар `(deck_id, term)` с выгрузкой из БД: ни пропусков, ни лишних

Проверка после заливки:
```sql
SELECT deck_id, COUNT(*) AS total,
       COUNT(*) FILTER (WHERE image_url IS NOT NULL) AS with_img
FROM words WHERE deck_id IN (...)
GROUP BY deck_id ORDER BY deck_id;
```
