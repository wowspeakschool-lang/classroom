# Контроль качества — ежедневный разбор заявок преподавателей

Задача Анны от 10.11.2026: каждый день в 10 утра смотреть «Контент» →
«Контроль качества» на платформе и разбирать сообщения преподавателей тем же
алгоритмом, которым разбирали 33 сообщения 02.11.2026.

## Откуда берутся сообщения

Учитель ставит ⚑ прямо в задании — при просмотре урока или при проверке
домашки. Сообщение падает в таблицу `classroom_feedback`:

| поле | что в нём |
|---|---|
| `lesson_id`, `block_id`, `item` | куда показывает учитель (item — номер пункта внутри блока) |
| `body` | что он написал |
| `context` | `preview` (смотрел урок) или `review` (проверял работу) |
| `enrollment_id` | чья работа, если из проверки |
| `status` | `open` · `fixed` · `not_error` |
| `reply` | наш ответ, учитель видит его в колокольчике |

Список открытых:

```sql
select f.id, f.created_at, c.slug, u.sort_order as unit, l.title as urok,
       b.sort_order + 1 as blok, b.type, f.item, f.body, f.context
from classroom_feedback f
join classroom_lessons l on l.id = f.lesson_id
join classroom_units u on u.id = l.unit_id
join classroom_courses c on c.id = u.course_id
left join classroom_blocks b on b.id = f.block_id
where f.status = 'open'
order by f.created_at;
```

## Алгоритм разбора

По каждому сообщению, по порядку:

1. **Прочитать блок целиком** (`select payload from classroom_blocks where id = …`)
   и, если сообщение из проверки, посмотреть ответ ученика. Учитель часто
   пишет коротко: «неверный ответ» — какой именно, видно только по payload.
2. **Решить, что это:**
   - **ошибка в данных** — неверный ключ, опечатка, картинка спорит с ключом,
     дубль варианта, перепутан порядок. Чиним миграцией, с копией блока
     в таблицу `classroom_backup_…`;
   - **не ошибка** — задание верное, учитель ошибся или не знал правила курса
     (перевод, звук у написанного слова, порядок пар в `match` и т. п.).
     Объясняем в ответе, ссылаясь на правило;
   - **не чинится данными** — нужна запись, картинка, правка платформы или
     решение Анны. Тогда сообщение **не закрываем**, а выносим строкой в
     `builds/vychitka_ot_vas.md` (или в список «Что ждём от вас», если нужно
     действие Анны) и пишем в ответе, чего ждём.
3. **Правка не пересчитывает уже сданное** (решение Анны 15.10.2026): если из-за
   неверного ключа у учеников стоят ошибочные ✗, учитель правит их руками —
   так и пишем в ответе.
4. **Закрыть сообщение** с ответом, который учитель прочитает:

```sql
update classroom_feedback
   set status = 'fixed',          -- или 'not_error'
       reply = 'Исправлено: … . Уже сданные работы не пересчитываются.',
       resolved_at = now()
 where id = '…'::uuid;
```

   **Исправленное закрываем без комментария** (решение Анны 11.11.2026):
   `status = 'fixed'`, `reply` пустой — учитель видит, что ошибка принята и
   устранена, и этого довольно. Текст ответа пишем только там, где без него
   непонятно: «не ошибка» (почему) и «ждём запись / картинку / правку
   платформы» (чего ждём). Тогда одной-двумя фразами по-русски.
5. **Записать итог**: сколько разобрано, сколько правок, что осталось ждать.
   Строкой в `builds/gotovnost.md` и в ответ Анне в чат.

## Чего не делаем

- Не закрываем сообщение без разбора и без ответа — учитель ждёт ответа
  в колокольчике.
- Не правим ключ «на всякий случай»: сначала смотрим payload и картинку,
  потом решаем.
- Не трогаем правила курса, закреплённые решениями Анны (список — в
  `CLAUDE.md`), даже если учитель просит обратного: отвечаем «не ошибка»
  и объясняем. Если учитель настаивает — выносим вопрос Анне.
- Один урок не правим, если его в это же время правит другой чат.

## Если заявок нет

Так и пишем: заявок нет. Ничего не придумываем и список «Что ждём от вас»
этим не нагружаем.
