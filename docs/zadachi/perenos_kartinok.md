# Задача: вынуть картинки из базы в файлы

Поставлена 14.10.2026, Анна согласна. Делается в отдельном чате.
Перед работой прочитать `CLAUDE.md` и `HANDOVER.md` в корне.

## Что не так

В старых курсах картинки вписаны прямо в задания строкой `data:image/…;base64,…`,
а не лежат файлами со ссылкой. Правило `CLAUDE.md` «только ссылки, никогда
base64» соблюдается только в новых курсах (SM2, SM3, GG).

Замер 14.10.2026:

| курс (slug) | блоков с base64 | объём payload |
|---|---|---|
| `wow-dragon-1` | 866 | 69 МБ |
| курс без slug (судя по всему, Wow Dragon 2 — проверить) | 830 | 56 МБ |
| `sm0` | 186 | 7,6 МБ |
| `sm1` | 247 | 6,5 МБ |

Всего 2129 блоков и около 8,8 тыс. вхождений `data:image`; 138 МБ из 141 МБ всех
payload в `classroom_blocks`. Все эти блоки — в **опубликованных** уроках.

Из-за этого урок открывается медленно, браузер не кэширует картинки,
«Озвучить пачкой» по курсу Wow Dragon тянет около 70 МБ одним запросом.

## Где лежит base64 — не только в `html`

| тип блока | блоков | вхождений | где |
|---|---|---|---|
| quiz | 738 | 4868 | `questions[].image`, `options[].image` |
| text | 376 | 454 | `html` (`<img src=…>`) |
| speaking | 370 | 370 | `image` |
| match | 166 | 969 | `pairs[].left_image` / `right_image` |
| flashcards | 158 | 705 | `cards[]…` |
| sort | 157 | 941 | `groups[].items[].image` |
| sequence | 88 | 354 | `items[].image`, `image` |
| task | 39 | 43 | `html` |
| order | 19 | 19 | `image` |
| hotspot | 13 | 13 | `image` |
| exact_input | 4 | 39 | `items[]…` |
| gaps | 1 | 1 | `image` |

Пути в таблице — по рендеру и редактору в `index.html`, сверить по живым данным.
Нужен **рекурсивный обход payload**: любая строка, которая целиком `data:image…`,
и любой `src="data:image…"` внутри html-строк. В `index.html` уже есть
`edExtractImages` / `edExtractAll`, но они переносят картинки только из `html`
(около 10 % вхождений) и по одному уроку — для массового переноса не годятся,
но показывают, как уже принято: загрузка в бакет `uploadToBucket`.

## Главная ловушка: байты не должны идти через модель

Base64 нельзя читать через `execute_sql` в ответ модели и нельзя вписывать в SQL
(см. `CLAUDE.md`, «Картинки»): испорченная картинка не заметна сразу. Все байты
обрабатывает скрипт. Через MCP идут только ссылки, id блоков и md5.

Варианты, как добраться до байтов (выбрать с Анной):

1. **Скрипт в контейнере с прямым доступом к базе.** Нужен секрет окружения
   (строка подключения Postgres или service-ключ Supabase) и разрешённый хост
   `vtcxghsqymwkyiogpndf.supabase.co` — см. `read_documentation`, темы
   `environment.secrets` и `environment.network`. Настраивает Анна в
   настройках окружения.
2. **Кнопка в редакторе, которую нажимает Анна.** Массовый режим «вынуть
   картинки по курсу»: браузер Анны с её входом читает блоки, грузит картинки в
   бакет и сохраняет блоки. Секретов не нужно, но это правка `index.html`
   и долгий прогон в браузере.

Куда класть: по `CLAUDE.md` картинки — в `media/` репозитория (отдаются с
`https://classroom.wowteach.ru/media/`). Но здесь до 100 МБ, и они раздуют
историю git; бакет `classroom-media` (папка, например, `<курс>/legacy/`) может
оказаться разумнее. Решить с Анной до начала, с цифрой итогового объёма на руках:
сначала посчитать число **уникальных** картинок (md5) и их вес после пересжатия
в webp.

## Как делать безопасно

1. Посчитать уникальные картинки по md5. Одинаковые картинки — один файл.
2. Перед заменой — резервная копия затронутых строк
   (`create table classroom_blocks_backup_b64_<дата> as select …`). Удалять её
   только с согласия Анны.
3. Файлы выложить и **проверить, что каждая ссылка отвечает 200**, до того как
   менять блоки. Если файлы в `media/`, это значит дождаться деплоя GitHub
   Pages из `main`.
4. Заменять по `id` блока; заменять только строку картинки, остальной payload
   не трогать.
5. Сверка после: в затронутых блоках не осталось `data:image`; число ссылок
   равно числу вынутых вхождений; несколько уроков каждого курса открыть
   глазами и показать Анне.
6. Начать с одного урока, показать Анне, потом курсами.

## Связь с работой по сдаче домашек

В ветке `claude/gracious-gauss-tk5iet` лежит ненакаченная миграция
`docs/migrations/classroom_submit_review_model.sql` (HANDOVER, 8.1). Она при
накате копирует заданные уроки ученикам (`classroom_lesson_snapshots`).
**Картинки лучше вынести до неё** — иначе копии уроков у учеников снимутся
с base64 и их тоже придётся чистить (`blocks` в `classroom_lesson_snapshots`).
Если миграцию к этому времени уже накатили, обойти и эту таблицу.

`edSave` в той же ветке уже сохраняет урок через `classroom_save_lesson`,
которой в базе пока нет — **эту ветку не сливать в `main`** до наката миграции.
