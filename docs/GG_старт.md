# Go Getter — с чего начать

Этот файл нужен, чтобы новый чат начал перенос без пересказа. Всё, что здесь
написано, уже проверено на Super Minds 3 — его перенесли этим же способом,
9 юнитов + финальный тест, 676 блоков.

Файл общий на все курсы GG. Сейчас в работе два чата параллельно:

| Чат | Что переносит | Своя ветка |
|---|---|---|
| A | **GG1** | `claude/gg1` |
| B | **GG2 + GG3 Test** | `claude/gg2` |

## 🟥 Ветку резать не от `main`

Всего, что перечислено ниже, **в `main` нет**: `main` разошёлся с рабочей
веткой 233 коммита назад, последний общий предок — коммит, который добавил
CLAUDE.md. Там нет ни `tools/sm3_build.py`, ни `media/sm3/`, ни документов
SM3, ни этого файла. Чат, начатый от `main`, будет изобретать всё заново.

Поэтому первым делом:

```bash
git fetch origin claude/charming-volta-8wralr
git checkout -b claude/gg1 origin/claude/charming-volta-8wralr   # чат A
git checkout -b claude/gg2 origin/claude/charming-volta-8wralr   # чат B
```

Если ветка `claude/charming-volta-8wralr` к тому времени уже влита в `main` —
резать от `main`, но сначала убедиться, что `tools/sm3_build.py` на месте.

## Два чата одновременно — что чьё

Курсы в базе разные, поэтому в Supabase чаты друг другу не мешают. Мешают они
друг другу в git. Правило простое: **каждый чат трогает только свои файлы.**

| Чат A (GG1) | Чат B (GG2 + GG3 Test) |
|---|---|
| `tools/gg1_build.py` | `tools/gg2_build.py`, `tools/gg3_build.py` |
| `docs/GG1_*` | `docs/GG2_*`, `docs/GG3_*` |
| `media/gg1/` | `media/gg2/`, `media/gg3/` |
| `migrations/gg1_*` | `migrations/gg2_*`, `migrations/gg3_*` |

**Не трогает никто:** `tools/sm3_build.py` (он шаблон, с него копируют),
`index.html`, `media/shared/`, `media/sm2/`, `media/sm3/`, документы SM2 и SM3.

**CLAUDE.md не правит никто из двух.** Обоим будет что туда дописать — копите
в своём `docs/GGN_доработать_руками.md` и в конце отдайте одним списком, иначе
две ветки разъедутся на одном и том же файле.

## Что берётся из SM3 без переделки

| Файл | Что в нём |
|---|---|
| `tools/sm3_build.py` | **шаблон сборщика**: словарь `LESSONS`, `check()` (проверка payload), `sql_for()` (миграция), флаг `--chunks` (вставки кусками для `execute_sql`). Копируется в `tools/ggN_build.py` — общий не дорабатываем |
| `tools/sm3_cut.py` | нарезка листа-сетки на отдельные карточки |
| `tools/sm3_gen_card.py` | догенерация одиночной карточки (`OPENAI_API_KEY`) |
| `tools/sm3_pdf_frames.py` | вырезание картинок из PDF выгрузки |
| `tools/sm3_media_docx.js` | docx со списком аудио и видео для методиста |
| `media/shared/` | приветствия, похвалы, 👍/👎 — общие для всех курсов, новых не рисуем |

Разделы CLAUDE.md «База», «Картинки», «Озвучка», «Перенос ДЗ из PDF-выгрузки
«Взнания»» и «Проверка перед заливкой» действуют **полностью**. Это не общие
слова: там собраны ровно те грабли, на которых стоял SM3.

## Порядок работы

1. **Разведка выгрузки.** Собрать id файлов Drive по юнитам в
   `docs/GGN_выгрузка_файлы.md` (образец — `docs/SM3_выгрузка_файлы.md`).
   У домашки обычно пара `.txt` + `.pdf`: `.txt` даёт текст, `.pdf` — картинки
   и отметки верных ответов.
2. **Листы промптов на картинки** → `docs/GGN_листы_промптов.md`. Один промпт =
   один лист-сетка, потом режется. Грабли нарезки — в `docs/SM3_листы_промптов.md`.
3. **Нарезка** в `media/ggN/uN/`, webp, качество 88 для карточек с мелким
   текстом, 78–82 для объектов.
4. **Сборка и заливка** юнит за юнитом: все домашки юнита → тест этого же
   юнита → коммит → следующий юнит. Тест отдельным заходом не делаем.

У чата B порядок тот же, но GG3 Test — одиночный урок: этапы 1, 3 и 4 без
генерации листов, если своих картинок ему не нужно.

## Что уже стоило времени на SM3 — не повторять

* **Заливка идёт `execute_sql`, а не `apply_migration`.** Длинный `do $mig$`
  отваливается по таймауту 60 с. Порядок: создать юнит и уроки одним `with`,
  потом вставки блоков кусками по 5–8 (`--chunks <lesson_id> --per-chunk 7`).
  `DELETE` — только внутри CTE. Файл миграции всё равно кладём в `migrations/`.
* **Проверка payload до заливки — обязательна.** `check()` ловит: `correct` не
  на том варианте, дубли вариантов, повтор правых значений в `match`,
  расхождение `words` и `sentence` в `order`, число пропусков в `gaps`,
  несуществующий файл в `media/`. После заливки — контрольный `select`: число
  блоков, типы, отсутствие оставшихся `@@MEDIA@@`.
* **У `task` нет поля `image`** — картинка кладётся прямо в `html`. У `speaking`
  и `truefalse` поле `image` есть.
* **Варианты квиза не перемешиваются при показе.** Если ставить верный всегда
  первым, ребёнок считает ответ по позиции — позиции разводить руками.
* **«Пустой» блок в выгрузке обычно не пустой.** Каждый «Открытый вопрос» и
  каждый блок без текста открывать картинкой страницы и смотреть глазами.
* **Верный ответ виден только при увеличении**: отмечен тот вариант, у которого
  **нет** пустого чекбокса. Вырезать область с вариантами и увеличивать втрое.
* **Выгрузка врёт.** На SM3 трижды ключ в `.txt` расходился с картинкой в PDF —
  верить PDF, расхождение записывать в «доработать руками».
* **Большой PDF через `download_file_content` роняет MCP-сервер Drive**
  (10 МБ → ~13.6 МБ ответа, «message too large»). Спасает `read_file_content`:
  он отдаёт текстовый слой. PDF до ~4 МБ качаются нормально, ответ ложится
  файлом в `tool-results/`.
* **Номера блоков для методиста пишем как в редакторе** (`sort_order + 1`).
* **Аудио и видео не обсуждаем в чате** — строкой в `docs/GGN_доработать_руками.md`
  и в docx для бакета. Блок всё равно создаём пустым, чтобы номера не поехали.
* **Две части одной домашки — один урок**, прощание первой части и приветствие
  второй сводятся в блок-перемычку.
* **Раскраски выбрасываем**, содержание переносим в `match` теми же парами.
* **Фотографий детей не берём** — ни из выгрузки, ни генерацией. Сканы
  учебника с людьми (комиксы, сцены) брать можно: правило про генерацию.

## Как отдавать медиафайлы

Методист скачивает их со «Взнания» сама. Список собирается запросом к базе
(пустые `url`, `audio`, `sample`) и выгружается в docx копией
`tools/sm3_media_docx.js`. Файлы кладутся в бакет `classroom-media`, папка
`ggN/uN/`, имя `ggN_u<юнит>_hw<домашка>_b<блок>.mp4|.mp3` — номер блока как в
редакторе. Ссылки в блоки прописывает чат.

## 🟥 Вопросы к Анне перед стартом

1. **Полные названия курсов** для `classroom_courses.title` — «Go Getter 1»,
   «Go Getter 2», «Go Getter 3»? От них зависят и префиксы файлов, и папки
   в `media/`.
2. **Где выгрузки** — id папок Google Drive по каждому курсу.
3. **Сколько юнитов и есть ли финальные тесты** — чтобы сразу заложить
   нумерацию `sort_order`.
4. **GG3 Test — это что именно?** Итоговый тест курса, который переносим
   целиком позже, или отдельный вступительный? От ответа зависит, заводить ли
   курс «Go Getter 3» с одним юнитом-тестом или ждать остальное.
5. **Те же ли правила, что в SM3**: без раскрасок, без фотографий детей, тест
   заливается вместе со своим юнитом.
6. **Пополнены ли кредиты OpenAI** — без них этап 2 не сдвинется. На SM3
   из-за этого остались недоделанными две карточки Unit 2 и три наскальных
   рисунка Unit 6.
