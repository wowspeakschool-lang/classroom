## Что не работает сейчас

Листание внутри задания в платформе уже есть: `roundsOn` в
`src/public/homework/blocks.tsx` (порог `QSTEP_MIN = 3` в `state.ts`) включает
показ «по одному» у **квиза**, **«верно/неверно»** и **«впиши ответ»** — у тех
типов, где несколько пунктов лежат в одном блоке.

У `order` так не получается: `OrderBlock` читает `p.words` — один массив слов,
то есть ровно одно предложение на блок. Поэтому серия из трёх-шести
предложений — это три-шесть отдельных блоков, и ученик видит подряд три-шесть
одинаковых экранов с одинаковым заголовком, не понимая, сколько их ещё.

**Тем же блоком собираются и слова из букв** («Собери слово: hen» — `words`
там не слова, а буквы). Так что правка нужна сразу для двух видов серий:
«Составь предложение» и «Собери слово». Разница одна: у слов подпись своя
у каждого элемента, у предложений общего заголовка обычно хватает.

Пример: SM1 Unit 5 ДЗ 5, блоки 6, 7, 8 — «Составь предложение из дневника
Милы» три раза подряд.

## Что просим сделать

### 1. Несколько предложений (или слов) в одном блоке `order`

Добавить в payload необязательный массив `items`:

```json
{
  "title": "Составь предложения из дневника Милы",
  "items": [
    { "words": ["On","Mondays","I","watch","TV","for","two","hours."],
      "sentence": "On Mondays I watch TV for two hours." },
    { "words": ["I","play","tennis","for","one","hour."],
      "sentence": "I play tennis for one hour." },
    { "words": ["On","Fridays","I","play","football","for","one","hour."],
      "sentence": "On Fridays I play football for one hour." }
  ]
}
```

У каждого элемента те же поля, что сейчас у блока: `words`, `sentence`,
необязательные `image`, `audio`, `audio_tts`, `prompt`.

**`prompt` обязательно показывать** — это подпись самого элемента, над фишками.
Общий заголовок блока («Собери слова 🔤») один на все элементы, а что именно
собрать, пишется у каждого. Без этого не переносится «Собери слово»:

```json
{
  "title": "Собери слова из букв 🔤",
  "items": [
    { "prompt": "hen", "words": ["h","e","n"], "sentence": "hen",
      "image": "https://classroom.wowteach.ru/media/sm0/u1/hen.webp" },
    { "prompt": "hat", "words": ["h","a","t"], "sentence": "hat" },
    { "prompt": "ham", "words": ["h","a","m"], "sentence": "ham" }
  ]
}
```

`image` у элемента — своя картинка к этому слову или предложению; сейчас она
лежит на уровне блока и при переносе должна уехать внутрь элемента.

**Старые блоки не трогаем.** Если `items` нет, а есть `words` — работает ровно
как сейчас. Проще всего внутри `OrderBlock` привести payload к одному виду:
`const items = p.items ?? [{ words: p.words, sentence: p.sentence, image: p.image, audio: p.audio }]`.

### 2. Листание — то же самое, что у квиза

При трёх и более элементах включать `roundsOn` и компонент `Rounds`, как уже
сделано в `ExactInputBlock` и `TrueFalseBlock`: показывать по одному элементу,
кнопки «← Предыдущий / Следующий →», точки-индикаторы, подпись вида
«предложение 2 из 3». При одном-двух элементах показывать их подряд, как
сейчас у квиза с двумя вопросами.

### 3. Ответ ученика

Сейчас `OrderBlock` сохраняет `ctx.set(id, { order: [...слова] })`.
Для нескольких предложений — по образцу «впиши ответ», ключ = номер элемента:

```json
{ "0": { "order": ["On","Mondays","I","watch","TV","for","two","hours."] },
  "1": { "order": [...] } }
```

Старый формат (`{ "order": [...] }`) продолжать читать как ответ на
единственный элемент — иначе потеряются уже сданные домашки.

В `model.ts` признак «задание выполнено» для `order` сейчас:

```ts
case 'order':
  return Array.isArray(a.order) && a.order.length === (p.words ?? []).length
```

Нужно считать выполненным, когда собраны **все** элементы.

### 4. Проверка учителем

В `TeachAnswer` показывать каждое предложение отдельной строкой: что собрал
ученик и что было задумано (`sentence`), с той же отметкой «верно / неверно»,
что и сейчас.

### 5. Редактор

В редакторе блока «Составь предложение» — возможность добавить и убрать
предложение внутри одного блока и поменять их местами. Остальные поля
(картинка, звук) у каждого предложения свои.

## Что сделаем мы после выкладки

Сведём существующие серии в один блок миграцией: три-шесть подряд идущих
`order` с одинаковым заголовком станут одним блоком с `items`. Домашки от
этого станут короче на 2–5 шагов каждая. Сами ничего в платформе не правим.
