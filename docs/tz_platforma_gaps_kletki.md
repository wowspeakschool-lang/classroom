# ТЗ платформе: клеточка на букву в пропусках «впиши буквы»

Решение Анны 06.11.2026 («18 просим»). Превью, как это выглядит сейчас и как
должно, — `docs/tz_platforma_gaps_kletki.html`, опубликовано по ссылке
https://claude.ai/artifact/WCWm4Ddjg2Hb3DGxakPuqT

## В чём дело

В блоке `gaps` с `mode: 'type'` пропуск рисуется **одним полем**. Его ширина
считается по длине верного ответа (`blocks.tsx`, `GapsBlock`):

```ts
const len = Math.max(1, ...x.accept.map((w) => w.length))
const w = `calc(${len + 0.6}ch + 16px)`
```

Границ между буквами нет, поэтому **на глаз не отличить, сколько букв вписывать**:
одну, две или три. Поля на 1 и на 2 буквы различаются на несколько пикселей.
Нагляднее всего в диктанте SM1 Unit 4 Test («сосиска»): в одном слове пропуск
на две буквы и пропуск на одну, а поля почти одинаковые.

## Что просим

1. Рисовать пропуск **N клеточками** по числу букв верного ответа, а не одним
   полем. Клеточка — отдельное поле ввода на одну букву.
2. Между клеточками просвет 2–4 px, чтобы границы читались.
3. Ввод идёт слева направо: после заполненной клеточки курсор сам переходит
   в следующую, по Backspace — возвращается в предыдущую.
4. Если в `accept` варианты разной длины, число клеточек берётся из
   `accept[0]`; засчитываются по-прежнему все варианты.
5. Вставка целого слова из буфера раскладывается по клеточкам.
6. Режимов `drag` и `choice` это не касается — там поле другого вида.

## Со стороны контента менять нечего

Число букв уже известно: это длина ответа в `accept[0]`. Сейчас платформа
считает по ней только ширину поля. Под правило попадают диктанты SM1 юнитов 0–4
(пять блоков, 25 слов, переведены в `gaps` 05.11.2026) и все задания
«послушай слово и впиши буквы» — SM0 и SM1.
