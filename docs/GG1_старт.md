# GG1 — с чего начать

Этот файл нужен, чтобы новый чат начал перенос GG1 без пересказа. Всё, что
здесь написано, уже проверено на Super Minds 3 — его перенесли этим же
способом, 9 юнитов + финальный тест, 676 блоков.

🟥 **Первое, что нужно подтвердить Анне** — собрано списком в конце файла.

## Что берётся из SM3 без переделки

| Файл | Что в нём |
|---|---|
| `tools/sm3_build.py` | **шаблон сборщика**: словарь `LESSONS`, функция `check()` (проверка payload), `sql_for()` (миграция), флаг `--chunks` (вставки кусками для `execute_sql`). Для GG1 копируется в `tools/gg1_build.py` — не дорабатывается общий, курсы живут отдельно |
| `tools/sm3_cut.py` | нарезка листа-сетки на отдельные карточки |
| `tools/sm3_gen_card.py` | догенерация одиночной карточки (ключ в `OPENAI_API_KEY`) |
| `tools/sm3_pdf_frames.py` | вырезание картинок из PDF выгрузки |
| `tools/sm3_media_docx.js` | docx со списком аудио и видео для методиста (запрос к базе + таблица по юниту) |
| `media/shared/` | приветствия, похвалы, 👍/👎 — общие для всех курсов, новых не рисуем |

Разделы CLAUDE.md «База», «Картинки», «Озвучка», «Перенос ДЗ из PDF-выгрузки
«Взнания»» и «Проверка перед заливкой» действуют для GG1 **полностью**. Это
не общие слова: там собраны ровно те грабли, на которых стоял SM3.

## Порядок работы

Тот же, что был на SM3, четырьмя этапами:

1. **Разведка выгрузки.** Собрать id файлов Drive по юнитам в
   `docs/GG1_выгрузка_файлы.md` (как `docs/SM3_выгрузка_файлы.md`). У каждой
   домашки обычно пара `.txt` + `.pdf`; `.txt` даёт текст, `.pdf` — картинки и
   отметки верных ответов.
2. **Листы промптов на картинки** → `docs/GG1_листы_промптов.md`. Один промпт =
   один лист-сетка, потом режется. Образец и грабли нарезки —
   `docs/SM3_листы_промптов.md`.
3. **Нарезка** в `media/gg1/uN/`, webp, качество 88 для карточек с мелким
   текстом, 78–82 для объектов.
4. **Сборка и заливка уроков** юнит за юнитом: все домашки юнита → тест этого
   же юнита → коммит → следующий юнит. Тест отдельным заходом не делаем.

## Что уже стоило времени на SM3 — не повторять

* **Заливка идёт `execute_sql`, а не `apply_migration`.** Длинный `do $mig$`
  отваливается по таймауту 60 с. Порядок: создать юнит и уроки одним `with`,
  потом вставки блоков кусками по 5–8 (`--chunks <lesson_id> --per-chunk 7`).
  `DELETE` — только внутри CTE. Файл миграции всё равно кладём в `migrations/`.
* **Проверка payload до заливки — обязательна.** `check()` ловит: `correct` не
  на том варианте, дубли вариантов, повтор правых значений в `match`,
  расхождение `words` и `sentence` в `order`, число пропусков в `gaps`,
  несуществующий файл в `media/`. После заливки — контрольный `select`: число
  блоков, типы, отсутствие оставшихся `@@MEDIA@@`.
* **У `task` нет поля `image`** — картинка кладётся прямо в `html`. У `speaking`
  и `truefalse` поле `image` есть.
* **Варианты квиза не перемешиваются при показе.** Если ставить верный всегда
  первым, ребёнок считает ответ по позиции — позиции надо разводить руками.
* **«Пустой» блок в выгрузке обычно не пустой.** Каждый «Открытый вопрос» и
  каждый блок без текста открывать картинкой страницы и смотреть глазами.
* **Верный ответ виден только при увеличении**: отмечен тот вариант, у которого
  **нет** пустого чекбокса. Вырезать область с вариантами и увеличивать втрое.
* **Выгрузка врёт.** На SM3 трижды ключ в `.txt` расходился с картинкой в PDF —
  верить PDF, расхождение записывать в «доработать руками».
* **Большой PDF через `download_file_content` роняет MCP-сервер Drive**
  (10 МБ → ~13.6 МБ ответа, «message too large»). Спасает
  `read_file_content`: он отдаёт текстовый слой. PDF до ~4 МБ качаются
  нормально, ответ ложится файлом в `tool-results/`.
* **Номера блоков для методиста пишем как в редакторе** (`sort_order + 1`).
* **Аудио и видео не обсуждаем в чате** — строкой в `docs/GG1_доработать_руками.md`
  и в docx для бакета. Блок всё равно создаём пустым, чтобы номера не поехали.
* **Две части одной домашки — один урок**, прощание первой части и приветствие
  второй сводятся в один блок-перемычку.
* **Раскраски выбрасываем**, содержание переносим в `match` теми же парами.
* **Фотографий детей не берём** — ни из выгрузки, ни генерацией.

## Как отдавать медиафайлы

Методист скачивает их со «Взнания» сама. Список собирается запросом к базе
(пустые `url`, `audio`, `sample`) и выгружается в docx тем же
`tools/sm3_media_docx.js` — у него данные зашиты в файле, для GG1 делается
копия `tools/gg1_media_docx.js`. Файлы кладутся в бакет `classroom-media`,
папка `gg1/uN/`, имя `gg1_u<юнит>_hw<домашка>_b<блок>.mp4|.mp3` — номер блока
как в редакторе. Ссылки в блоки прописывает чат.

   три наскальных рисунка Unit 6.
