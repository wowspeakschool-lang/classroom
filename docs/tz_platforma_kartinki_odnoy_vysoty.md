# «Напиши ответ»: картинки пунктов — одной высоты

Нашла Анна 04.11.2026 на SM2 Unit 0 Test, блок 2 (диктант): «картинки разного
размера, очень некрасиво».

## Что не так

`ExactInputBlock` рисует картинку пункта так:

```tsx
<Img url={it.image} cls="kph kqimg" />
```

а в `homework.css`:

```css
.kph{ width:100%; border-radius:14px; object-fit:contain; max-height:min(40vh,320px); }
.kqimg{ max-height:min(32vh,260px); }
```

Размер задаёт **ширина**: картинка всегда растягивается на всю колонку, а высота
получается какая выйдет. Поэтому в одном задании книжный шкаф (264×360) выходит
узким столбиком под потолок в 260 px, а восковой мелок (360×83) — во всю ширину
экрана и выглядит в разы крупнее. Соотношения сторон у предметов разные по
природе: в этом задании от 0,70 до 4,34.

Задание выглядит рваным, и на дорогих местах — в тестах, где это диктант.

По базе таких заданий 143 в семи курсах, картинок в них 853: SM1 — 31 блок,
GG1 — 34, SM2 — 24, SM3 — 20, GG2 — 19, GG3 — 10, Holidays — 5.

## Что просим сделать

Для картинки **пункта** `exact_input` задавать высоту, а не ширину:

```css
.kei .kph{ height:140px; width:auto; max-width:100%; align-self:center; }
```

Тогда все картинки задания одного роста, широкий мелок остаётся широким, но не
крупнее остальных, а узкий шкаф не превращается в столбик. Высоту можно взять
другую — важно, чтобы она была одна на задание.

На телефоне ограничение по ширине (`max-width:100%`) само ужмёт самые широкие.

Блочную картинку (`payload.image` у `gaps`, `order`, `task`) это не трогает —
там полная ширина как раз нужна.
