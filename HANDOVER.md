| колонка | значения | смысл |

## 4. Пятнадцать типов блоков

`text · video · quiz · exact_input · match · task · embed · order · sort ·
flashcards · gaps · truefalse · speaking · sequence · hotspot`

Точные поля — в `index.html`: там и рендер (около строк 1100–1200), и редактор
(около 3200–4200). Ниже только то, на чём спотыкались.

**`gaps`** — пропуски размечаются **двойным** подчёркиванием: `I __go__ to
school`. Одинарное не распознаётся. Приём ответа — через
`classroom__gaps_accept`.

**`sequence`** («Расставь по порядку») — верный порядок задаётся **самим
порядком элементов в массиве `items`**, отдельного поля с ответом нет. Ученику
список показывается перемешанным, в редакторе — как есть. Поля: `title`,
`image`, `audio` на блок; `items[].text`, `items[].image`, `items[].audio`.
**Никогда не перемешивать `items` при генерации миграции** — это и есть ответ.

**`hotspot`** («Точки на картинке») — `image`, `points[].x`, `points[].y` в
**процентах** от размера картинки, `points[].text`, `points[].audio`, плюс
`extras[]` — лишние варианты (строка или `{text, audio}`). Отвлекающие варианты
озвучивать тоже, иначе по наличию звука видно правильные.

**`speaking`** — устное задание, **заменило** старую связку `task` +
`answer_kind:"audio"`. Поля в корне payload: `title`, `html`, `sample` (образец
для прослушивания), `image`, `needs_review`. Ученик записывает голос, ответ
уходит в `submissions/<auth.uid()>/`.

**`match`** — правые значения должны быть уникальны. Если повторяются, блок
надо делать `quiz`.

**`quiz`** — варианты это объекты, не строки: `{text, image, audio, …}`.
Картинку и аудио можно вешать и на сам вопрос, и на каждый вариант.

**`order`** — склейка `words` должна совпадать с `sentence`; расхождение обычно
в разных апострофах.

**`flashcards`** — не проверяется. Ученик нажимает «запомнил / повторил», и
карточка сразу переключается на следующую, без отдельной кнопки «дальше».

**`sort`** — `groups` → `items`, ответ `{assign:{"<индекс>":номер_группы}}`,
автопроверка по доле карточек в верной группе.

## 5. Как накатывать изменения в базу

В Claude Code — через `mcp__Supabase__apply_migration` с осмысленным именем
(`sm2_u6_hw1_new_face`, `classroom_submit_review_model`). Версии там
timestamp'ом, нумерация сквозная по всему проекту. **Схема `classroom_NNN_…`
из прошлых чатов — это было только имя файла**, который Анна вставляла в
SQL-редактор руками; в Claude Code она не нужна и больше не ведётся. Старый
счётчик (`claude/_classroom_счётчик.md` в проекте) доведён до 034 и закрыт.

Что уже накатано по интерфейсной линии, для истории — файлы лежат в
`docs/migrations/`:

| | что сделала |
|---|---|
| 028 | диагностика состояния, только `select` |
| 029 | CHECK на `type`: 10 → 13 (+ `gaps`, `truefalse`, `speaking`) |
| 030 | `completion_check` узнала три новых типа |
| 031 | политики бакета `classroom-media` |
| 032 | CHECK 13 → 14 (+ `sequence`) и `completion_check` |
| 033 | ветка подсчёта для `sequence` в `submit_block` |
| 034 | CHECK 14 → 15 (+ `hotspot`), `completion_check`, ветка подсчёта |
| 035 | **не накатана и не нужна** — чинила `ВАШ-ПРОЕКТ`, Анна отказалась |

### Приём: точечная вставка ветки в большую функцию

`classroom_submit_block` длинная (206 строк) и трогать её целиком опасно.
В 033 и 034 сделано так: достать текущее тело через `pg_get_functiondef`,
строковой заменой вставить новую ветку **перед якорем**
`elsif v_block.type = 'sort' then`, выполнить через `EXECUTE`. Три защиты в
начале: не применена ли уже, ровно ли один якорь, то ли число типов. Так
функция не переписывается по памяти.

**Правило, которое стоило ошибки: никогда не перезаписывать функцию, не увидев
её текущего тела.** И перед любым `UPDATE` — `SELECT` тем же условием.

### Политики бакета `classroom-media`

```
classroom_media_read         SELECT
classroom_media_insert       INSERT   редактор после входа
classroom_media_student_write INSERT  ученик, только submissions/<auth.uid()>/
classroom_media_update       UPDATE
classroom_media_delete       DELETE
```

Диагностика политик: смотреть **и `qual`, и `with_check`**. У `INSERT`-политик
условие лежит в `with_check`, и запрос только по `qual` показывает их как
отсутствующие — я на этом один раз зря поднял тревогу.

### Разметка `_tts`

Рядом с **пустым** полем `audio` кладётся ключ с суффиксом `_tts`:

```json
{ "text": "get up", "audio": "", "audio_tts": "get up" }
```

Значение — строка или `{text, voice}`. Кнопки «Озвучить пачкой» и «Озвучить этот
урок» обходят payload рекурсивно (`ttsCollect`) на любой глубине, синтезируют и
заполняют `audio`. Уже заполненный звук не трогается. В пачке можно выбирать
курс → юнит → **отдельные уроки**, не только целиком.

Мы только размечаем в миграциях — нажимает методист. В базе сейчас 2869 блоков
с ключами `*_tts`.

Инструкция для аккаунта, который генерирует контентные миграции, —
`Дополнение_к_промпту_переноса_ДЗ.md` в проекте Анны. Главное оттуда: `title`
блока **видит ребёнок**, поэтому никаких служебных кодов в заголовке.

## 7. Что сделано в интерфейсе

Всё уже в `main`, перечислено, чтобы не изобретать заново.

**Просмотр и роли.** `CR_VIEW = {role, variant, format}` и `crBlockVisible()` —
фильтр блоков по аудитории, варианту и длительности. Предпросмотр
разворачивается на весь экран. Кнопка «Просмотр» в списке материалов открывает
урок **сразу глазами ученика**, и роль сбрасывается на ученика при каждом
открытии; режим и длительность так не сбрасываются. Ученику видно по одному
блоку за раз.

**Слайды.** `slideHtml(p)`, `SLIDE_LAYOUTS` (9 раскладок), `SLIDE_THEMES`
(5 тем), `edSlideEditor()` — слайд собирается из данных по раскладке, а не
пишется руками в HTML.

**Отмена действий.** `ED_HIST` / `ED_REDO`, `edCheckpoint()` — снимок при
перерисовке и через 900 мс после остановки печати, глубина 60. Стрелки ↶ ↷ в
плавающей панели `#edDock` вместе с «Сохранить» и индикатором несохранённого
(`EDIT.savedJson`). Подтверждений при удалении звука, блока, задания и варианта
**нет и не нужно** — есть отмена.

**Редактор.** `edMoveTo` — перестановка блока вводом номера, с сохранением того,
какие блоки раскрыты (по тождеству объектов, не по индексам). Стрелки ↑ ↓.
`edMaskHtml` / `edUnmaskHtml` прячут base64 за токенами `⟦картинка N⟧`,
`edExtractImages` / `edExtractAll` переносят их в бакет. `edReadiness()` —
полоса готовности, видна **только методисту**. Миниатюры блоков через
`edFirstImage` + `BTHUMB`.

**Библиотека** — плитки с перетаскиванием, не дерево: `LIB`, `libRender()`,
`libCover()` (обложки рисуются SVG), `libDragInit()`, `libSaveOrder()`,
`libSnack()` с отменой, `libMenu` / `libRenameSave` / `libPub` / `libDelete`.
Есть стрелка «назад» внутри папки. После удаления папки страница не
выбрасывает в «Мои ученики». Открытие колесиком мыши — в новой вкладке.

**Поиск** — `Ctrl+K`: `findOpen` / `findDraw` / `findKey` / `findGo`.

**Цвета курсов.** `COURSE_TINTS` + `COURSE_RULES`; Wow Dragon — фиолетовый,
разные оттенки для первой и второй части. Шапка материала — бледная подложка с
обычным текстом и цветной полосой 4 px, не заливка с белыми буквами: «цвета
нужно спокойнее, красивее и прозрачнее».

## 8. Что дальше

По порядку, как договорились.

### 8.1. Механика сдачи и проверки — первое

Одна миграция, назвать по смыслу (`classroom_submit_review_model`).

`classroom_progress` + `status` (`in_progress` · `submitted` · `reviewed` ·
`retake`), `submitted_at`, `reviewed_at`, `teacher_score`, `retake_blocks uuid[]`.

`classroom_submissions` — переопределение вердикта учителем по каждому пункту и
ручная оценка блока. Частично уже есть `review_status`, `reviewed_at`,
`reviewer_note` — смотреть, что достроить, а не заводить второе поле рядом.

Четыре функции: завершить и отправить, переопределить вердикт пункта, выставить
итог, задать заново. И точечная правка `classroom_submit_block` — **перестать
отдавать оценку ученику и перестать автоматически закрывать урок**.

Как это выглядит для людей:

* ученик отвечает **вслепую**, без «верно/неверно» по ходу;
* кнопки «Проверить» после каждого блока **нет** — убрать;
* одна кнопка «Завершить и отправить», недоступна, пока не выполнено всё;
* после отправки ученик видит **только оценку** — процент и монетки. Захотел
  посмотреть задания — отдельная кнопка открывает домашку заново в режиме
  чтения;
* учитель проверяет, может переопределить вердикт по каждому вопросу,
  выставить оценку руками, включить «Показать верные ответы»;
* задать заново можно **и весь урок, и отдельные выбранные задания** —
  галочками.

Макеты: `docs/makety/classroom_sdacha.html` — пять экранов (выполняет /
отправлено / проверка учителем / оценена / на доработку).

**Состояние на 14.10.2026 (вечер):** миграция написана —
`docs/migrations/classroom_submit_review_model.sql`, **в базу ещё не накатана**.
Накатывать **вместе** с правкой `index.html` (ученический экран, проверка,
колокольчик), не раньше: после неё старый интерфейс перестанет показывать
проценты и вердикты. Что в ней сверх плана выше, по решениям Анны:

* **порога нет** — `pass_threshold` в логике сдачи не участвует (был только у
  вокабуляра и диктанта); оценку и переделку решает учитель;
* попыток **без ограничения**, история — `classroom_progress.history`;
* отправить можно, только когда **отвечен каждый пункт каждого задания**
  (`classroom__block_complete`); ученику называются номера недоделанных;
* **заданное не меняется**: при назначении урок копируется ученику
  (`classroom_lesson_snapshots`), правки методиста его не трогают — ни задания,
  ни их состав; проверка идёт по копии. Прохождение берёт задания через
  `classroom_run_blocks`, а не из `classroom_blocks`;
* редактор сохраняет урок **по id задания**, а не по месту
  (`classroom_save_lesson`; `edSave` уже переделан). Раньше `upsert` по
  `(lesson_id, sort_order)` при перестановке оставлял id на месте и переносил
  под него чужое содержимое;
* ответы и оценки **не удаляются** вместе с заданием — внешние ключи
  `classroom_submissions.block_id` и `classroom_grades.block_id` сняты;
* **комментарии учителя** — отдельная таблица `classroom_comments`: ко всей
  домашке, к заданию или к пункту, сколько угодно, без привязки к оценке
  (`classroom_comment_save` / `classroom_comment_remove`). Ученик видит их
  после проверки или при переделке (оба события шлют уведомление), в
  `classroom_lesson_grade` → `comments`. При переделке ответ уходит в историю,
  а комментарий остаётся — в нём написано, что исправить;
* уведомления «отправил» и «переделать» — вид `info` с `payload.event`
  (`submitted` / `retake` / `reviewed`); CHECK на `kind` не трогали.

Пробный прогон через `execute_sql` упирается в подтверждение в приложении
(в журнале Postgres большие запросы не появлялись вовсе) — запускать, когда
Анна рядом и готова подтвердить.

Известное и сознательно отложенное: правильные ответы лежат в `payload`,
и ученик технически может увидеть их через инструменты браузера. Чтобы
спрятать, нужно перемешивать варианты на сервере, а это переделка всех
типов. Для детей риск мал, Анна решила не делать.

### 8.1а. Для разработчика: встраивание в кабинет ученика

У учеников свой кабинет на другой платформе; разработчик подключит classroom
туда. Учитель задаёт домашку и **дату сдачи** (календарь на странице ученика,
`classroom_set_lesson_active(…, p_deadline)` → `classroom_assignments.deadline_at`).
Ученик видит заданные уроки у себя. Функции, которые нужны кабинету:

| что | функция |
|---|---|
| список уроков курса со статусом, сроком, оценкой | `classroom_student_lessons(student, course)` → `hw_status`, `deadline_at`, `score` (только после проверки) |
| задания урока (замороженная копия) | `classroom_run_blocks(enrollment, lesson)` |
| ответ на задание (сохраняется сразу, без оценки) | `classroom_submit_block(block, enrollment, answers)` |
| можно ли отправлять, что не доделано | `classroom_lesson_grade(enrollment, lesson)` → `can_finish`, `incomplete` |
| «Завершить и отправить» | `classroom_finish_lesson(enrollment, lesson)` |
| результат после проверки | `classroom_lesson_grade(enrollment, lesson)` → `score`, ответы; вердикты — если учитель включил `show_answers` |
| уведомления | таблица `classroom_notifications`, `recipient_kind='student'` |

Ученика classroom узнаёт по `classroom_student_links (auth_id → student_id)`:
сейчас таблица пустая, её наполнение — часть встраивания.

### 8.2. Ученический вид

Перенести в `index.html` из `docs/makety/uchenik_3varianta.html` — **тёплая
тема, она утверждена**. Домашка ученика должна вписываться в его кабинет, но
иметь своё лицо. Шрифт крупнее. Эффекты умеренные, `prefers-reduced-motion`
уважать.

**Отдельно: не перерисовывать экран целиком при ответе.** Анну раздражало
мигание. В макете сделано точечными обновлениями DOM — `taskEl(i)`,
`markDone(i)`, `sync()`, без пересборки страницы. Переносить вместе с этим
подходом.

### 8.3. «Предложить правку» для преподавателя

Решение принято и закрыто: **преподаватели не получают прав редактировать
материалы.** Анна обсуждала с руководителем — через classroom всё идёт от лица
школы, а свои правки преподавателей это ломает. Пересматривать будем по отзывам,
не раньше.

Вместо этого — кнопка «Предложить правку» у блока: преподаватель пишет, что не
так с конкретным заданием, методист видит список, привязанный к блокам.

### 8.4. Журнал

Макет `docs/makety/classroom_zhurnal.html` — таблица с фильтрами по программе и

Вопрос, который раньше считался тупиком, **снят**: связь преподаватель ↔ ученик

## 9. Как проверять правки `index.html`

Три шага, все три обязательны. Третий появился после настоящей поломки.

1. **`node --check`** на вырезанном JS. Ловит синтаксис.
2. **Перекрёстная проверка вызовов из атрибутов.** Вытащить все имена функций из
   `onclick`, `onchange`, `oninput` и прочих атрибутов и сверить со списком
   объявленных функций. Это чинит дыру в шаге 1: при переписывании куска файла
   я однажды снёс `edTtsOpen`, `edTtsOpenCb` и `edTtsRun` — файл остался
   синтаксически верным, `node --check` прошёл, и «Озвучить» молча перестала
   работать. В консоли было `Uncaught ReferenceError: edTtsOpenCb is not
   defined`.
3. **Для SQL** — `pglast.parse_sql()` и `parse_plpgsql()` до накатывания.

Ещё из своих ошибок:

* `.btn` в этом файле — **основная** кнопка, `.btn.sec` — второстепенная. Если
  покрасить `.btn` в белый, побелеют все главные действия.
* Убирая `if(ME.isEditor){…}`, не оставить висящий `else`. Лучше
  переформулировать в `if(!ME.isEditor){…}`.
* Названия разделов брать из кода, не придумывать: «Мои ученики», «Задать
  материал», тип блока называется «Материал», а не «Текст». Заголовок раздела и
  надпись на закладке должны совпадать.

## 11. Решения, которые закрыты

* Преподаватели **не** редактируют материалы. Вместо прав — «Предложить правку».
* Ученик отвечает вслепую, отправляет один раз, когда выполнено всё.
* После сдачи ученик видит только оценку; задания — отдельной кнопкой, в режиме
  чтения.
* Задать заново можно весь урок или выбранные задания.
* Тёплая тема ученического вида.
* Адаптации под группу в домашках нет — только в планах уроков.
* Подтверждений при удалении в редакторе нет, работает отмена.
* Плейсхолдеры `ВАШ-ПРОЕКТ` остаются как отметки «нужно аудио».
* Голос озвучки по умолчанию `en_US-amy`.
* Wow Dragon — фиолетовый, разные оттенки для первой и второй части.
* Комментарии учителя — односторонние: ученик читает, но не отвечает (14.10.2026).
